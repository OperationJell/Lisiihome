# LISII HOME · 0.1.0

Первая сборка уютного домика для двух человек под Windows 10/11 x64.

## Как запустить

1. Запустите `LISII-HOME-Setup-0.1.0.exe` и установите приложение.
2. Откройте **LISII HOME**. После прозрачной заставки появится домик.
3. Для первого знакомства нажмите **«Пока побыть дома без подключения»**. В этом режиме оба персонажа находятся в домике; в настройках можно переключить управляемого персонажа.

Установщик не подписан коммерческим сертификатом издателя. Это предварительная сборка, собранная в Linux; установка и особенности прозрачных окон на настоящем Windows ещё не проверены.

## Управление

| Действие | Результат |
|---|---|
| Перетащить крышу левой кнопкой | Перемещение домика |
| Колесо мыши над домиком | Изменение размера |
| Крестик в верхнем углу | Выход |
| Минус | Свернуть в панель задач |
| Нажать на диван | Сесть, включить эмблему YouTube и секундомер |
| Нажать на стол / компьютер / стул | Сесть за своё рабочее место |
| Нажать на кровать | Лечь; кровать вмещает одного человека |
| Нажать на свободный пол перед диваном | Встать |
| Нажать на своего персонажа | Выбрать настроение |
| Нажать на кота | Облачко «Эу», видимое обоим |
| Кнопка `1/2` или `2/2` | Открыть подключение |
| Шестерёнка | Настройки и обновления |

У девушки за компьютером белые наушники, у мужчины — чёрные. У мужчины за компьютером периодически появляется устройство IQOS с лёгкой анимацией дымка. Четыре выражения: усталость с каплей, нейтральное, сонное с Zzz и радостное. Пятое настроение — бургер над головой. Секундомер считает время текущего пребывания на диване. Телевизор показывает эмблему, воспроизведение YouTube не реализовано и не требуется для этой версии.

Положение и размер сохраняются отдельно на каждом компьютере. При отключении монитора окно возвращается в доступную область. Настройки, адрес сервера и личный ключ комнаты хранятся в `%APPDATA%\lisii-home\settings.json` (папка может называться по имени приложения). Не передавайте этот файл другому игроку: в нём ваш ключ входа.

## Игра вдвоём в одной сети

В меню «Пуск» после установки есть дополнительный ярлык **LISII HOME Server**.

1. На одном компьютере запустите **LISII HOME Server**. Оставьте окно сервера открытым. Он покажет свои адреса.
2. На этом же компьютере запустите обычную игру, в поле сервера укажите `ws://localhost:8787` и выберите **«Создать комнату · девушка»**.
3. Скопируйте код комнаты.
4. На втором компьютере установите ту же игру. Укажите адрес, показанный сервером для локальной сети, например `ws://192.168.1.15:8787`. Введите код и нажмите **«Войти · парень»**.
5. При следующих запусках адрес, комната и роль восстановятся автоматически.

Windows может запросить разрешение для сервера в локальной сети. IP-адрес `localhost` на втором компьютере использовать нельзя — он означает сам второй компьютер. Если локальный IP сервера изменится, адрес подключения нужно изменить один раз или закрепить IP в роутере.

Гость закрепляется за первым подключившимся устройством. Третий человек занять комнату не сможет. Если гость потерял настройки или сменил компьютер, администратор может дважды нажать **«Освободить место гостя»**, после чего гость снова входит по коду. Отключённый персонаж становится полупрозрачным; его место и настроение сохраняются.

## Игра через интернет

**Публичный сервер в эту поставку не развёрнут.** Установщик сам по себе не создаёт облачный сервер. Для игры из разных сетей нужен постоянно работающий сервер с публичным HTTPS/WSS-адресом. С исходниками поставляется готовая серверная часть и конфигурация Docker.

На сервере с Docker:

```sh
docker compose -f server/compose.yaml up -d --build
```

Снаружи нужен HTTPS reverse proxy с поддержкой WebSocket (пример `server/Caddyfile`). Замените пример домена своим. Приложение использует `wss://ваш-домен`. Для комнаты сохраняется отдельный личный ключ каждого игрока; роли назначает сервер. Хранилище `lisii-data` должно быть постоянным. Не удаляйте его при обновлении контейнера. Для резервной копии сохраняйте `rooms.json`; там хеши ключей и состояния комнат.

Без Docker, Node.js 24:

```sh
cd server
npm install --omit=dev
npm start
```

Переменные сервера: `PORT` (по умолчанию 8787), `DATA_FILE` (путь к rooms.json). Проверка работоспособности — `GET /health`. Сервер рассчитан на один процесс и небольшой частный проект. Для публичного массового сервиса нужны дополнительные эксплуатационные меры и масштабируемое хранилище.

## Обновления

В приложении реализованы проверка обновления, загрузка с прогрессом и установка по кнопке **«Установить и перезапустить»**. Автоматического прерывания игры нет.

**Публичный источник обновлений пока не настроен.** Для его подключения:

1. Разместите релизы на постоянном HTTPS-адресе.
2. Укажите этот адрес в настройках обоих приложений один раз.
3. Для выпуска увеличьте `version` в package.json, соберите приложение и разместите рядом `latest.yml`, установщик `.exe` и `.exe.blockmap` из `dist`.
4. Публикуйте `latest.yml` последним, когда файлы уже доступны. Настройки игроков при обновлении сохраняются.

В build-конфигурации домен `updates.invalid` — технический placeholder для формирования метаданных, обращения к нему не выполняются, пока пользователь не настроил источник. Перед настоящим выпуском замените его на свой HTTPS-адрес. Проверка обновлений возможна в установленной версии, а не в режиме разработки. Сквозная установка обновления на Windows ещё не проверена. Текущая сборка не подписана; перед широким распространением настройте подпись установщиков и проверку издателя.

## Для разработки

```sh
npm ci
npm test
npm start
```

Сборка установщика на Windows:

```sh
npm run build:win
```

Сборка на Linux без Wine:

```sh
npm run build:linux-win
```

Linux-обёртка использует встроенный бинарный `UninstallerReader` electron-builder для извлечения деинсталлятора без запуска Windows-кода. Обычная Windows-сборка не использует эту обёртку. GitHub Actions workflow в `.github/workflows/windows.yml` собирает артефакты на Windows по тегу `v*` или вручную; он не настроен на автоматическую публикацию.

`npm run server` запускает отдельный WebSocket-сервер. `npm run preview` служит для локального просмотра интерфейса в браузере; прозрачное окно, размещение поверх других окон и нативные обновления требуют Electron.

## Что проверено

- Сервер: два клиента, назначение ролей, запрет третьего игрока, защита от подмены роли, смена настроений и места, занятость кровати, событие кота, восстановление после перезапуска, сброс приглашения.
- Отрисовка и интерфейс: загрузка прозрачных слоёв, посадка на диван/за стол, смена локального персонажа, меню из пяти настроений, секундомер, сон, голод, кот и локальное сохранение. Это автоматические тесты DOM и Canvas, не настоящий Windows UI.
- Собран установщик NSIS x64 с встроенным приложением и сервером. Проверены комплектность упаковки и контрольные суммы.

Ограничения проверки: среда не предоставляет Windows; установщик, нативное перетаскивание, прозрачность поверх других программ и установка обновления не были выполнены на Windows. Браузерный канал предпросмотра в среде оказался недоступен. До распространения нужна проверка на двух Windows-компьютерах.
